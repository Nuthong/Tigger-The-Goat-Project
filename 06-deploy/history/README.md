# ประวัติโรงแรม 2000-01-01 .. 2026-12-31

สคริปต์ SQL ชุดนี้เติมประวัติการดำเนินงานย้อนหลัง 27 ปีลงฐานที่โหลด `schema.sql`, `roles.sql` และ `seed.sql` แล้ว
- เพิ่มเฉพาะแถวข้อมูล ไม่แก้โครงสร้าง `03-database/` ซึ่งล็อกไว้
- ใช้ได้เฉพาะ temp table และ `pg_temp` function ซึ่งหายไปเองเมื่อจบ session

## วิธีรัน

```bash
cd 06-deploy
docker compose run --rm db-loader        # เริ่มจาก seed สะอาด
docker compose run --rm history-loader   # นำเข้าประวัติ ใช้เวลาราว 5-10 นาที
```

ถ้าจะรันด้วย psql ตรง ๆ ต้องใช้บัญชี superuser:

```bash
psql -h localhost -p 5433 -U postgres -d roombooking -v ON_ERROR_STOP=1 -f 06-deploy/history/00_run.sql
```

ตัวเลือก:
- `-v scale=0.3` (หรือ env `HISTORY_SCALE`) ลดปริมาณความต้องการห้องลง ค่า `1.0` คืออัตราเข้าพักจริงราว 65-84% ต่อปี
- `-v seed=42` (หรือ `HISTORY_SEED`) เปลี่ยนชุดสุ่ม ถ้าใช้ seed เดิมจะได้ข้อมูลชุดเดิมทุกครั้ง

สคริปต์ปฏิเสธการรันซ้ำ เพราะใส่แถว `history.import` ไว้ใน `audit_log` ถ้าจะนำเข้าใหม่ให้รัน `db-loader` ก่อน

## ได้อะไรบ้าง (scale 1.0)

| ข้อมูล | ที่มา |
|---|---|
| การจอง ~342,000 รายการ | จำลองทีละวันเข้าพัก: จำนวนคำขอ, lead time, จำนวนคืน, ประเภทห้อง, จำนวนห้องและแขก ห้องไหนเต็มจะลองประเภทใกล้เคียง ถ้ายังไม่ได้ถือว่าคำขอนั้นหลุดไป |
| อัตราเข้าพัก | ฤดูกาล, วันในสัปดาห์, วันหยุดยาว และเหตุการณ์จริงในกรุงเทพฯ: SARS, ปิดสนามบิน 2008, ชุมนุมราชประสงค์ 2010, น้ำท่วม 2011, ชัตดาวน์ 2014, โควิด (ปิดโรงแรม เม.ย.-มิ.ย. 2020) |
| ลูกค้า ~248,000 คน | สัญชาติเปลี่ยนตามยุค เช่น แขกจีนเพิ่มขึ้นจนถึงปี 2019 และปี 2020-2021 เป็นคนไทยเกือบทั้งหมด แขกประจำราว 28% โดยคนที่เคยพักบ่อยมีโอกาสกลับมามากกว่า ลูกค้า seed ทั้ง 988 คนได้เข้าพักหลังวันสมัครของตัวเอง |
| พนักงานตามยุค | อดีตพนักงานเป็น `is_active = false` ทุกแถวที่อ้างถึงพนักงาน (รับจอง, เช็คอิน/เอาท์, ออกใบกำกับ, ทำความสะอาด, แจ้งซ่อม) อยู่ในช่วงที่คนนั้นทำงานจริง |
| ราคาห้อง | rate plan รายปี 2000-2025 (rack rate, weekend, high season ปีใหม่) ราคาต่อคืนทุกห้อง = `fn_quote_stay / คืน` เหมือนที่แอปคำนวณ |
| บริการเสริม | ไม่เกินเพดาน BR-29 ราคาตามแคตตาล็อกของปีนั้น ซักรีดและมินิบาร์มีเฉพาะการเข้าพักที่เกิดขึ้นจริง |
| การชำระเงิน | จ่ายล่วงหน้า / มัดจำคืนแรก / จ่ายที่โรงแรม PromptPay เริ่มปี 2017 ยกเลิกก่อนเส้นตาย 48 ชม. คืนเงินเต็ม ยกเลิกช้าหรือ no-show เก็บค่าคืนแรก |
| ใบกำกับภาษี | 1 ใบต่อการเช็คเอาท์ ออกโดยพนักงานเคาน์เตอร์ รายการเขียนรูปแบบเดียวกับแอป VAT 7% |
| งานแม่บ้าน ~1.1 ล้านงาน | ทำความสะอาดหลังเช็คเอาท์, รายวันระหว่างพัก (แขกแขวนป้ายห้ามรบกวนได้), turndown ห้องสวีท, deep clean รายไตรมาสในวันที่ห้องว่าง, ตรวจห้องก่อนรับแขก VIP และหลังซ่อม |
| งานซ่อม | พบตอนทำความสะอาด หรือแขกแจ้งระหว่างพัก ถ้าต้องปิดห้อง ห้องนั้นจะงดขายจนซ่อมเสร็จ และมีงานส่วนกลางราว 2 ใบต่อเดือน |
| room_status_log | available → cleaning → available, available → maintenance → available และปิดโรงแรมช่วงโควิด |
| รีวิว | คะแนนและข้อความสัมพันธ์กับการเข้าพัก เช่น ถ้าห้องเสียระหว่างพักคะแนนจะต่ำลง และจะชมอาหารเช้าได้เฉพาะคนที่ซื้ออาหารเช้า |
| audit_log | แถวเดียวกับที่ trigger ของการจองเขียน บวกกับรายการที่แอปเขียนเอง (ใบกำกับ, no-show, งานซ่อม, rate plan) ทุกแถวลงเวลาตามเหตุการณ์จริง |

สถานะของข้อมูลช่วงปัจจุบันคิดจากเวลาที่รันสคริปต์ ได้แก่ แขกที่กำลังพักอยู่, การจองล่วงหน้าถึง 31 ธ.ค. 2026, งานแม่บ้านวันนี้ที่ยังค้าง, ห้องที่กำลังทำความสะอาดหรือกำลังซ่อม และใบงานที่ยังเปิด

## ตรวจความสัมพันธ์ก่อน COMMIT (`08_verify.sql`)

ระหว่างนำเข้าจะปิด trigger ไว้ด้วย `session_replication_role = replica` เหตุผลคือ trigger กันจองซ้อนต้องไล่ทุกแถวของห้องนั้นทุกครั้งที่ insert จึงช้าแบบ O(n²) ส่วน trigger audit ก็จะลงเวลาเป็นตอนที่รันสคริปต์

เพื่อแทนสิ่งที่ปิดไป สคริปต์ตรวจ 20 ข้อจากแถวจริงในตาราง ถ้าข้อใดไม่เป็น 0 จะ ROLLBACK ทั้งหมด:

1. ห้องเดียวกันไม่มีแขกสองกลุ่มในคืนเดียวกัน (BR-5)
2. ถ้าเล่นการจองย้อนตามเวลาจริง trigger BR-5 จะไม่มีวันเด้ง รวมถึงการจองที่ถูกยกเลิกแล้วมีคนมาจองห้องนั้นแทน
3. จำนวนแขกอยู่ระหว่างจำนวนห้องกับความจุรวม (BR-7)
4. ราคาต่อคืน = `fn_quote_stay` / จำนวนคืน
5. บริการเสริมไม่เกิน BR-29
6. พนักงานทุกคนที่ถูกอ้างถึงทำงานอยู่ในวันนั้นจริง
7. เงิน: เช็คเอาท์แล้วยอดคงเหลือเป็น 0, ยกเลิกแล้วเก็บไว้ไม่เกินค่าคืนแรก, ไม่มีการจองไหนจ่ายเกิน
8. การเช็คเอาท์แต่ละครั้งมีใบกำกับ 1 ใบ ยอดรวม ยอดแต่ละบรรทัด และ VAT ตรงกัน
9. ทุกห้องที่เช็คเอาท์มีงานทำความสะอาด 1 งานในวันเช็คเอาท์ (เหมือน trigger)
10. งานระหว่างพักอยู่ในช่วงเข้าพักและห้องของการจองนั้น
11. แม่บ้านทำทีละงาน ช่วงเวลาทำงานของคนเดียวกันไม่ทับกัน
12. แขกเช็คอินหลังห้องทำความสะอาดหรือตรวจเสร็จแล้ว
13. ไม่มีใครพักในห้องที่ปิดซ่อม หรือช่วงที่โรงแรมปิด
14. `room_status_log` ของแต่ละห้องต่อกันเป็นสายเดียว
15. รีวิวเกิดหลังเช็คเอาท์เท่านั้น
16. ลูกค้ามีตัวตนก่อนการจองแรก และมีเลขบัตรเมื่อเคยเช็คอิน
17. วันที่อยู่ในช่วง 2000-01-01 .. 2026-12-31 และไม่มีเหตุการณ์ที่ลงเวลาในอนาคต
18. audit trail ตรงกับวงจรของการจองทุกรายการ
19. สถานะห้องปัจจุบันตรงกับงานที่ยังค้าง
20. FK ทุกเส้นของแถวที่นำเข้า
